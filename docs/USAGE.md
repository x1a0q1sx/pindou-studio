# 智能拼豆板工作台 PinDou Studio · 使用文档

> 一句话：**把你的屏幕变成一块发光底板**。程序按真实物理尺寸 1:1 渲染钉位网格，
> 你把透明拼豆板叠在屏幕上、板角对准括标，就能照着屏幕逐颗放豆。
>
> 适用场景：2.6mm 迷你豆（104 钉 / 28×28cm 透明板）与 5mm 标准豆（Perler / Hama）。

| 最近更新 | 2026-10（随程序实现同步维护） |

## 启动方式

- **桌面快捷方式「拼豆工作台」**（推荐，日常使用）：双击即可启动完整的 Electron 版（物理校准 / 指定屏全屏 / 防休眠全部可用）。首次运行会自动补装依赖与构建产物，之后秒开。
- **开发模式** `npm run dev`：Vite 热更新 + Electron，改代码实时生效；
- **仅浏览器** `npm run dev:web`：不启动 Electron，浏览器打开 http://127.0.0.1:5173（物理尺寸检测等系统能力降级为手动）；
- **运行已构建版本** `npm run start`：加载 dist 构建产物（桌面快捷方式即此路径）。

> 应用是无边框窗口：**拖动顶部工具栏空白处**可移动窗口，**双击工具栏空白处**最大化/还原；右上角有**最小化 / 最大化 / 关闭**三颗窗口按钮（关闭有红悬停提示）。

## 1. 环境与启动脚本

### 1.1 运行环境要求

| 项目 | 要求 |
| --- | --- |
| Node.js | v20 及以上（开发实测 v24.15.0） |
| 操作系统 | Windows 10/11（完整能力）；macOS / Linux 可运行，但物理尺寸自动检测依赖 WMI，仅 Windows 可用 |
| 浏览器（Web 模式） | Chromium 内核优先（Chrome / Edge），支持 File System Access API 与 OffscreenCanvas |
| 屏幕 | 分辨率越高、缩放比越明确，1:1 精度越好；触摸屏可用但不是必需 |

依赖极简：运行时只有 `react` / `react-dom` / `zustand` 三个包，其余（颜色科学、量化算法、渲染器、导出器）全部手写，无第三方算法库。

### 1.2 安装

```powershell
cd <本项目根目录>        # 即 clone 或解压后的 pindou-studio 目录
npm install
```

> PowerShell 下**不要**用 `&&` 连接命令，请用 `;`（例如 `npm install; npm run dev`）。

### 1.3 脚本一览

| 脚本 | 命令 | 作用 | 何时用 |
| --- | --- | --- | --- |
| **dev** | `npm run dev` | 并行启动 Vite（`127.0.0.1:5173`）与 Electron，等 Vite 就绪后自动拉起桌面窗口 | **日常开发主用**。只有它能拿到 WMI 物理尺寸、真实多显示器列表、`%APPDATA%` 文件读写 |
| **dev:web** | `npm run dev:web` | 只启动 Vite 开发服务器，用浏览器打开 `http://localhost:5173` | 没有 Electron 环境、或只想快速看 UI 时。会走浏览器降级分支（见第 8 节） |
| **build** | `npm run build` | 先 `tsc --noEmit` 做全量类型检查，再 `vite build` 产出 `dist/` | 发布前 / 提交前验收。**类型不通过就不会产出 dist** |
| **test** | `npm test` | Vitest 跑 `tests/` 全量用例（含 2026-10-11 补齐的 persistence/dirtyRect/layers/exportRaster 四块） | 改核心算法/存取/导出后快速回归 |
| **lint** | `npm run lint` | ESLint 扁平配置（2026-10-11 建立）：错误级拦截 unused-vars/rules-of-hooks；exhaustive-deps 为警告级存量挂账 | 提交前；`npm run lint:fix` 自动修复可修项 |
| **start** | `npm run start` | 用 Electron 直接加载已构建的 `dist/`（环境变量 `PDB_START_DIST=1`） | 想以「成品」形态体验，而不是开发热更新 |
| **preview** | `npm run preview` | 用 Vite 的静态服务器预览 `dist/`（默认端口 4173） | 只想在浏览器里验收构建产物 |

典型顺序：

```powershell
npm install          # 一次性
npm run dev          # 桌面开发（推荐）
npm run build        # 验收
npm run start        # 以成品形态跑 dist
```

若只想在浏览器里验收构建产物：`npm run build; npm run preview`。

> 端口约定：开发服务器 **5173**，preview **4173**。若被占用，Vite 会自动顺延端口，注意看终端输出。

## 3. 核心功能指南

### 3.1 屏幕信息获取与手动校准

**自动检测**：桌面模式下程序读取系统显示器信息（分辨率、工作区、缩放比）并并行查询 WMI 的显示器物理厘米数，直接算出「每设备像素多少毫米」与分轴 PPI，给出**零输入的高精度初始校准**。

**你要做的**：只在第 4 步「物理校准」里核对一次即可（详见第 5 节）。

**可靠性设计**：

- 校准档按显示器唯一标识（`id|分辨率|缩放`）记录，换显示器会自动生成对应的初始校准；
- 分辨率或缩放变化时，程序会提示「检测到分辨率或缩放变化，建议重新校准」；
- **虚拟显示器**（如远程桌面虚拟屏、采集卡虚拟屏）拿不到物理尺寸，会在显示器选择器中**置灰并告警**「无法进行 1:1 物理校准」，此时只能靠标尺拖拽法手动校准。

### 3.2 底图生成

在「板参数」表单里可以调：行数、列数、钉距(mm)、豆点直径占比（0.5–1.0）、格间距、板边留白(mm)、豆点样式（圆形 / 方形 / 圆环）、网格线显隐、主线每 N 格加粗（默认 10）、行列编号显隐与间隔、标尺显隐。

> **格间距设计说明**：格间距无独立参数，由钉距与豆点直径占比推导：**格间距 = 钉距 × (1 − 豆点直径占比)**（BoardConfig 无独立 gap 字段）。因此调整钉距或豆点直径占比时，格间距会自动跟随变化，两个参数永远不会互相矛盾。

**一键预设**（`PresetChips`）：

| 预设 | 钉数 | 钉距 | 有效区 | 说明 |
| --- | --- | --- | --- | --- |
| `p104` | 104×104 | 2.6923mm | 28×28cm | **推荐 · 默认**，2.6mm 透明板 |
| `p78` | 78×78 | 2.6923mm | 21×21cm | 中号板 |
| `p52` | 52×52 | 2.6923mm | 14×14cm | 小号板 |
| `p29` | 29×29 | 5mm | 14.5×14.5cm | 5mm 大豆系列 |
| `p58` | 58×58 | 5mm | 29×29cm | 5mm 大豆大板 |
| 自定义 | 任意 | 任意 | — | 直接在表单里填 |

**整板尺寸核对 + 实测反算钉距**：尺寸区下方实时显示「豆阵 X×Ycm · 整板 Zcm」——豆阵=列数×钉距（不含板边），是你实物板上**豆心网格**的跨度。若与实物板（如 28cm）对不上：拿尺量实物板豆心网格的宽度（不含板边），填进「实测豆阵宽 mm」点「反算钉距」，程序按 `钉距 = 实测宽 ÷ 列数` 写回。例：104 钉板量得 280mm → 钉距自动回到 2.6923mm，拼豆模式即按 28.0cm 排布。**注意**：这修的是「设计尺寸」；若设计尺寸本就对（显示 28.0cm）但屏幕上看着偏大偏小，那是屏幕物理尺寸校准问题，见第 5 节「整板对位」。

**物理精度铁律**（程序内部已实现，用户无需干预，但值得知道）：Canvas 的像素缓冲按 CSS 尺寸 × `devicePixelRatio` 建立，所有几何计算在设备像素域完成；每格边界**独立取整**，绝不「首格取整 + 累加固定步长」，因此 104 格的累计误差恒小于 0.5 个设备像素，相邻格宽最多差 1 像素。拼豆模式下缩放被强制锁在 1:1，禁止任何非整数缩放。

### 3.3 图片导入与像素化

完整链路：**导入图片 → 裁剪 → 像素化参数 → 减色 → 落到画布**。

1. 工具条「导入图片」按钮，或快捷键 `Ctrl+Shift+I`；也可以直接把图片拖进画布区。支持 png / jpg / webp / gif / bmp，会校验类型与体积。
2. **裁剪框**：按目标板的行列比例（如 104:104）锁定，拖动裁剪框选区。适配方式三选一（悬停按钮有说明）：
   - **完整（默认，推荐）**——整张图都出现在板上；非正方形图两侧留空格，**绝不缺内容**；
   - **裁满**——图片放大铺满整板，超出板外的部分被裁掉（横图会丢左右、竖图会丢上下）；
   - **拉伸**——变形填满整板，比例失真，一般不推荐。
3. **像素化参数**：目标格数、采样方式（区域平均 / 中心取样）、亮度 / 对比度 / 饱和度预处理、背景色透明处理，以及**去背景**开关——自动从图片四边取色识别背景色，把与边缘**连通**的相似色区域清成空格（主体内部的同色区域不受影响）。背景有渐变/光影时调大容差，主体被误吞时调小；纯色图开启后不会变空板。
4. **减色**：目标颜色数 2–64 滑杆（默认 32，对照片细节更友好）+ 实时预览 + 抖动（Floyd–Steinberg）开关 + 少量色精确保留 / 去杂色 / 合并近似色 / 色度门控 / 高光保护 / 近似色号合并。
5. 生成后图案直接落到画布，并报告「识别出 N 色，已匹配到某色板色号，最大色差 ΔE=x.x（某色号）」。
   - **笔刷大小**（画笔/橡皮通用）：选中画笔或橡皮后，工具栏出现「笔刷 N×N」步进器（1–9）。橡皮调大可以一次擦一片；悬停时光标框会实时预览盖章范围。

全部重活跑在 Web Worker 里（解码 → **线性光空间**按格采样平均（含高光保护）→ **色度门控** → Median Cut 量化 → **Lab K-means 精修** → 鲜艳度增强 → 近似色合并 → 高光色保障 → CIEDE2000 匹配到品牌色板 → 可选抖动 → **近似色号合并** → 去杂色 → 零拷贝回传），带进度回调、可取消。区域平均在**线性光空间**进行（sRGB 直接平均会偏暗、压饱和——「发灰」的经典来源之一）。Worker 或 OffscreenCanvas 不可用时会自动回退到主线程执行，**功能不缺失**。

#### 图纸 Web · 社区现成图纸

左侧工具栏的「图纸 Web」按钮（放大镜图标）打开对话框，直接从 **Reddit 拼豆社区**检索别人做好的图纸并一键导入：

- **搜索**：填子版块 + 关键词（如 `pokemon` / `mario` / `pattern`），或点热门子版块 / 引导词 chip 快速浏览热榜。已内置建议版块 `r/PerlerBeads`、`r/beadsprites`（拼豆像素画，图纸质量高）、`r/IronBeads`、`r/HamaBeads`、`r/CrossStitch`。
- **导入**：点结果卡片「导入」→ 下载原图 → 走**上方完整像素化 / 配色管线**（自动匹配当前 MARD 色板），和导入本地图片一模一样。想看图纸的完整色号图例，点卡片「原帖」在系统浏览器打开。
- **只取图片帖**：GIF 动图、视频、纯文字帖会自动过滤，卡片缩略图走像素渲染（`image-rendering: pixelated`）看清网格。

**网络前提（重要）**：Reddit 是海外站，**国内通常要开系统代理**才能访问。桌面版走 Electron 网络栈，会**自动跟随系统代理**（如 Clash）——所以开了代理软件后，应用内直接就能搜。取图失败时不会静默，会给出「需代理 / 被限流 / 稍后再试」等可读提示。浏览器版受跨域限制无法直连，请用桌面版。**版权**：社区图纸多为同人创作，个人拼着玩无碍，商用需自行留意授权。

> 数据层 `core/patternSource.ts` 与网络层解耦（纯函数解析 Reddit JSON，已单测覆盖），日后接 Pixilart 等只增解析器、不改界面。

### 3.4 颜色识别与调色板管理

- 内置 5 套色板：**通用拼豆色板（96 色）**、**Artkal（2.6mm 迷你豆，225 色）**、**MARD（2.6mm 迷你豆，官方 221 色）**、**Perler（5mm 标准豆）**、**Hama（5mm MIDI，88 色）**。
- 颜色科学全部手写：sRGB ↔ linear ↔ XYZ(D65) ↔ Lab ↔ LCh、hex 解析、标准 **CIEDE2000** 与 CIE76 色差。
- 量化采用「**Median Cut + Lab K-means 精修**」两级流水（借鉴 libimagequant / pngquant 的做法）：中位切分给初始色板，再在 CIE Lab 空间跑数轮 Lloyd 迭代（12k 子采样、≤8 轮、收敛早退），显著降低整体色差；量化后自动做**鲜艳度增强**（vibrance：低饱和色提得多、高饱和色几乎不动，补偿均值量化导致的发灰；中性色/肤色不被染色；少量色精确路径不做增强）。
- **少量色精确保留**（自动配色对话框开关，默认开）：图片的非空格唯一色数 ≤ 目标色数时（像素画 / 线稿 / logo 常见），直接**原样保留每个原图色**，跳过量化和抖动，颜色零损失；超过时自动回退正常量化。
- **去杂色 + 合并近似色**（自动配色对话框两个开关，默认都开）：抗锯齿边缘和 JPEG 噪点常把图转出成片的「碎杂色」。去杂色是**智能判定**：孤立点若与邻域主色接近（ΔE≤12，抗锯齿/JPEG 噪点的特征）则并入主色；**与主色色差很大的孤立点视为有意设计的高对比细节（眼睛、点缀）予以保留**——细节和杂色不再被一刀切。开启抖动时自动跳过去杂色（抖动散点是故意的）。合并近似色把人眼难分的碎色（ΔE<8）按格数加权合并后再匹配色板。
- **色彩还原三增强**（自动配色对话框三个开关，默认都开，针对照片类图片的三大顽疾）：
  - **色度门控**（治「黑发识别成棕色」）：彩度 C* < 9 的格子（近黑 / 近白 / 低饱和灰）先折算成同亮度的中性灰再量化匹配。照片暗部普遍带 JPEG 噪点/白平衡暖偏（黑发的彩度仅 5–8），此前会被放大成深棕色号；门控后黑发只会落黑/深灰号，纯色区域的噪点色也先塌缩成同一灰阶。
  - **高光保护**（治「瞳孔反光糊成一片」）：某格内近白像素（亮度 ≥235 且通道差 ≤30）占比 ≥6% 时，该格改用高光簇均值而非整体均值，并且量化结果保证包含这一高光色——黑瞳孔里的 2px 白反光不再被大片暗部平均成糊色。
  - **近似色号合并**（治「一片黑识别出好几个色号」）：匹配完成后，色板上 ΔE2000 < 2.8（低于人眼分辨阈 JND）的两个**已用**色号，格数少的自动并入格数多的。与「合并近似色」互补：那个管量化阶段，这个管「不同量化色恰好映射到色板近邻色号」的情形。
- **Lab 暗区正确性**（色彩科学基座修复）：XYZ→Lab 的 κ 常数曾误写为 24389/100（正确 24389/27 ≈ 903.3），暗区 Lab 全面失真（L 偏暗、a/b 放大约 3.7 倍）——这是「黑发变棕」「暗部色号紊乱」的深层根因，已修复并加回归测试锚定。
- **匹配顺序**：先量化到 K 色（K ≤ 64），再把这 K 色匹配到色板，因此最多 64 × 250 = 16000 次色差计算，毫秒级完成；不会对上万格逐格匹配全色板。
- 你可以**逐色微调 / 替换**：选中一个色号，用「同色替换」（`R` 键）把全板该色换成另一色；也可以用颜色编辑器改 hex，或用**吸管**（`I` 键）直接从实物照片 / 屏幕上取色校正。
- 支持**用户自定义色板**，独立存储，与内置数据物理隔离；内置色板永不被修改。

### 3.6 按颜色高亮筛选与拼豆进度（核心体验）

这是本程序最重要的使用场景，完整流程：

1. 按 `P` **进入拼豆模式**。程序自动完成：选定显示器无边框全屏 → 锁 1:1 物理比例 → 切到「专注拼豆」布局 + 「暗夜发光底板」主题 → 开启防休眠 → 显示区块 A1 与四角 L 形对齐括标，并且**隐藏全部工具界面，只展示板子**。
   - **格子绝不缩小**：整板超出屏幕 1:1 可视区时自动**按屏建议最小分块**（如 1×2，只增不减），格子始终保持真实豆距，显示不全的部分按 `[` `]` 切区块查看。
   - **刻度尺自动避让**：进入拼豆时刻度尺自动隐藏（避免遮挡最左列），退出后原样恢复；拼豆面板与工具栏都有「刻度尺」开关可手动控制。
   - **格距自查**：拼豆信息条显示「每格 2.69mm」，悬停可看校准依据（屏幕物理尺寸假设）。更快的办法：点 `⚙` 展开高级面板，用底部的**「尺子核对 · 校准格子大小」**——拿一把真实直尺贴在屏幕上，拖动「屏宽/屏高假设」滑杆直到屏幕上那把 100mm 的尺与真尺等长，校准即时生效并按屏存档（也提供 21.5″/24″/27″/32″ 常见尺寸一键预设与「恢复自动」）。多屏时每块屏的假设不同，这是格子"看起来变小"的最常见原因。（这些联动可以在设置里逐项关掉；退出时会**逐项反向恢复**原来的布局、主题、视图，并关闭防休眠。）
2. 把透明板放到屏幕上，**板角对准括标**。
   > **紧凑悬浮控制胶囊**（拼豆模式下顶部居中的一颗小胶囊，不占一整行）：
   > 常显 `◀ │ ●B5 剩36 │ [●N 余240] [●M 余186] ▾ │ ✓ 拼完 │ 本区 │ ⚙ │ ✕`——
   > 当前色读数拼完后显示「已拼完」；后面跟**接下来要拼的色卡**（按剩余量最多排序，
   > 最多 2 张，**点谁直接切谁**，不用再猜箭头后面是谁）；`▾` 展开**完整色卡队列**
   > （本范围全部颜色按剩余排序，点谁切谁，已完成的置灰）。
   > 点 `⚙`「更多操作」在胶囊正下方展开**小浮窗**（区块导航 / 按色筛选 / 逐色进度 / 尺子核对 / **作为智能板**）。
3. **进入拼豆模式会自动开启「发光板」**：屏幕上**只亮当前色的未拼格**，已拼的熄灭、其他色纯黑 —— 与真实发光底板该亮的样子一致，一眼看出该色还剩哪些位置。
4. 切色三选一：**点胶囊上的下一色色卡**（最直接）、按 `N`、或 `Shift+N` 反向（当前色即最多时切次多者）。顺序都是**剩余量最多优先**（先把大头拼完，换色次数最少）；条上读数同步更新为「色号 + 剩 N 颗」。
5. 逐颗放豆，每放一颗就**单击一下对应格子**（或 `Shift+点击`）→ 板上该位置熄灭、剩余数实时递减；需要挪动图纸对位时直接**按住拖拽**平移（格距锁定 1:1，拖拽与单击互不干扰）。
6. 一个色拼完 → 点 `✓ 本色拼完`（或按 `Enter`）→ 确认弹窗「把 B5 标记为已拼完？将把 B5 的 36 颗全部标记为已放置」→ 确认后**自动跳到下一个待拼色**并刷新板面。
7. 整个区块放完 → 按 `]` 切到下一区块 → 屏幕引导「请把板子移动，使 A2 区左上角对准屏幕括标」。
8. 全部完成 → 点 `✕ 退出`（或按 `Esc`）→ **逐项恢复到进入前的状态**（布局 / 主题 / 缩放 / 筛选档位 / 当前色）。

**按色筛选档位**（`⚙` 高级面板里可随时切换，拼豆模式默认「发光板」）：

| 档位 | 效果 | 适用 |
| --- | --- | --- |
| **发光板** | **只亮当前色的未拼格**，已拼熄灭、其他色纯黑 | **拼豆模式默认**：与真实发光底板观感一致，一眼看出该色还剩哪些位置 |
| 正常 | 显示全部豆点 | 想通览整幅图时 |
| 仅本色 | 只显示当前色，其余极淡轮廓 | 想保留整体位置感 |
| 压暗 | 当前色发光，其余压暗 65% | 对比观察当前色在整图中的分布 |
| 隐藏 | 当前色以外完全隐藏（已拼格仍显示） | 最省杂光，但看不到「已拼了哪些」 |

> 「发光板」与「隐藏」的区别：前者把**已拼的格也熄灭**（还原真实底板状态）；后者只滤掉其他颜色，已拼格仍亮着。

**成品拼豆逆向**（导入别人已完成的拼豆作品，自己复刻）：

1. 导入成品照片/图纸 → 像素化参数页打开「**成品拼豆逆向**」开关（适配模式会自动切为拉伸，请用上一步的裁剪框框住拼豆区域本身）。
2. 参数页下方会出现**对位图**（照片 + 蓝色采样网格叠加）——旋转角、水平/垂直微调的效果一眼可见，判据：**每条网格线都从豆心穿过**，不再靠预览结果试错。
3. 照片明显拍歪/斜拍时，打开「**四角透视校正**」，拖动对位图上的 4 个黄色手柄框住拼豆区域四角——采样前程序会把该区域**拉正成矩形**再逐豆取色。
4. 逆向采样只取**豆心圆盘**（默认豆距的 32%，避开豆间黑缝），颜色比普通平均纯净得多。
5. 之后与普通导入一致：选色板（配色用 CIEDE2000）→ 生成图案 → 查看**逐色用量清单**（进度页签，即采购清单）与**分块建议**。
6. 进入拼豆模式逐区实现：拖拽平移图纸对位、单击标记已放、逐色计数。原作色号未必买得到——用颜色编辑器/吸管校正到你手头有的色号即可。

**色号清单**（左侧工具栏的「清单」按钮）：拿到别人图纸的**用料清单**（文本/表格里的「色号 数量」列表）时，点开粘贴进去，程序逐行解析并匹配到当前色板——同号直配；色号属于别的品牌色板（如 Artkal）时自动给**当前色板的最近色建议**（CIEDE2000，附 ΔE 值）；匹配不到的标「未匹配」不瞎猜。支持 `A1 ×120` / `B3 45` / `M15: 8` / `C2,200` 等写法与行首序号，自动算**合计颗数**，可一键复制规范化清单。

**分块模式**：当整块板（28cm）大于屏幕可视区时，程序会自动建议**最小分块**——横竖两个方向**独立**计算各自需要的刀数，屏幕宽度放得下就绝不横切；且采用**容量优先**切法：**第一块尽量占满一整屏，放不下的余量归到最后一块**（不是均分）。例如本机 2560×1600 屏（1:1 最多容 122×78 格）：横向 104 格放得下 → 不切；纵向超了 → 切 2，方案为 **1×2 = 首块 A1 104×78（整屏占满）+ 末块 A2 104×26（余量）**。整板放得下就不分块。每块仍渲染 L 形对齐括标与区块编号；进度面板的分块设置（横 N × 纵 M 步进器）可手动调整块数（块容量保持"首块尽量满"）。

> **换大屏自动合块**：分块跟着「拼豆目标屏」的容量走——从笔记本切到大显示器（整板 1:1 放得下）后，进入拼豆模式会**自动合并回单块**并提示；再切回小屏又会按新屏容量重新分块。多屏间热插拔/切换时，若正处在拼豆模式会立即重估。若你是在进度面板**手动**设定的块数（当分页用），程序只会在容量不足时被迫扩大、**绝不自动合并**你的手动方案。在「校准」页点选另一台显示器也会带出该屏存档的校准档（含整板对位精调），并按该屏重估分块。

> **暗色豆不再隐形**：发光底板（glowDark 主题）画布是纯黑底——黑/深色豆（如 MARD H6/H7）画上去几乎没有对比度，「压暗后看不到」。现在深色豆会自动补一圈**浅色救援描边**（板参数「网格与标注」的**暗色描边**开关，默认开）：每个豆位置一眼可辨、可数；筛选逐色拼的「压暗」模式下，深色豆也用更浅的压暗层保住轮廓。进阶组合：「豆上色号」+「暗色描边」同时开，深豆上白字标出 H6/H7，相邻深色系（黑 vs 深炭）也能靠色号区分。若你觉得描边多余，关掉开关即可回到纯净豆面。

**包边**：右侧面板「板参数」页签底部有「包边」区——选好色号（默认自动取当前色板里的黑色），点「加一圈包边」，程序沿**图案轮廓**加一圈豆子（8 邻域膨胀描边：圆形图案得到贴轮廓的一圈，不是外接方框；图案内部空洞的边缘同样描边；绝不覆盖已有豆子）。板内空间够就直接画；图案贴边或铺满全板时**自动扩板**（如 104×104 → 106×106）并把内容居中迁移，已放置标记一并保留。两种情况都支持 **Ctrl+Z 撤销 / Ctrl+Y 重做**（扩板路径会连同板尺寸与已放标记一起回退）。

**智能拼豆板 · 蓝牙探测（实验功能）**：「开始 / 帮助」面板 → 实验功能 → **智能板蓝牙探测（旧）**打开探测对话框（2026-09-30 起左侧工具栏「智能拼豆板」按钮直开的是「本机当作智能板」，真板子探测收纳到这里）——对标颂拼豆等 App 的「连接智能拼豆板」能力做的**第一、二层**：

1. **搜索**：走 Web Bluetooth 扫描附近 BLE 设备。Electron 没有内建蓝牙选择框，主进程已接管 `select-bluetooth-device`，扫到的设备列表会在对话框里自绘成可点选的清单（60 秒不选自动取消）。
2. **连接与枚举**：选中后连 GATT，列出该板全部**主服务**与**特征值**（含 R/W/N/I 属性位）。默认把 0xFF00–0xFFFF 厂商服务段整体授权（国产灯板绝大多数用这段），常见板子一次扫描即可看全；冷门 128bit 服务把 UUID 填进「附加授权」重新扫描。
3. **复制探测报告**：一键复制纯文本树（设备名/服务/特征/属性），发回来即可判断**第三层**——点灯协议是否可驱动（有未加密的可写特征 = 可以下一步做「逐格亮灯引导」；厂商加密握手 = 只能继续用屏幕 1:1 对位）。

说明：这是**探测与诊断工具，探测 ≠ 控制**——点灯指令尚未实现（取决于你的板子型号与协议开放性）。浏览器模式没有蓝牙选择框，此功能只在桌面应用（`npm run dev` 或打包版）可用。

**本机当作智能板**：入口在**左侧工具栏「智能拼豆板」按钮**（2026-09-30 起；也可从「开始 / 帮助」面板实验功能区、拼豆模式「更多操作」小窗的「作为智能板」按钮打开）——把**这台电脑反向变成一块智能拼豆板**（本项目是板子、被连的一方）：主进程按需编译并托管一个 C# 旁路（Windows 蓝牙外设角色 + GATT 服务 + BLE 广播），手机 App（酷猫系开放协议 / 颂拼豆 PIXDOU 协议，细节见 `docs/RESEARCH-BLE-SMART-BEAD-BOARD.md`）扫描连接后，把图案数据写进电脑，对话框里的**屏幕点阵实时点亮**——屏幕即灯板；所有收到的帧进事件日志（已知命令给中文摘要、未知命令给 hex），反向可发「实体按键·上一色/下一色」通知。

**手机图案上页面（设计模式小窗 + 画布点亮）**：旁路在跑时，设计模式**右下角出现「智能板」悬浮小窗**——实时显示手机下发的点亮图案（按 App 画的原色重绘点阵）、连接与下发进度状态，可折叠成小药丸。收到图案时若对话框没开会弹 toast 提醒。小窗里的动作：

- **画布点亮**：把主画布临时切成发光板显示（整板纯黑、只亮手机下发的格子，与拼豆模式同款效果）；再点「画布熄灭」还原你之前的筛选档位。不打扰正常编辑，不自动劫持画布。
- **清除**：清掉手机图案（与对话框、拼豆顶栏 chip 的清除行为一致，都会联动还原画布点亮）。
- **面板↗**：打开虚拟板面板（广播设置 / 回码控制 / 事件日志）。

> **它和「拼豆模式发光板」的区别（容易混淆，务必分清）**：
> - **拼豆模式发光板** = 日常拼豆用。本程序是**控制方**，电脑屏幕当发光底板，照着屏幕放豆子（主界面按 `P` 进入，顶部悬浮胶囊操作；手机点色号同样会点亮主画布）。
> - **本机当作智能板** = 手机 App 联调用。本程序是**被控方**，手机 App 连上电脑点色号，图案显示在设计模式右下角小窗（入口：左侧工具栏「智能拼豆板」）。

- **广播名限制（重要）**：Windows 把广播设备名收归系统托管（= 本机蓝牙适配器名/电脑名，代码改不了）。目标 App 若按 `pindou-` / `kmpd-` 前缀过滤设备列表，请到 Windows 设置 → 系统 → 重命名这台电脑为 `pindou-PC01` 这类名字再连；排障先用手机装 nRF Connect 验证「能搜到电脑」。
- 首次「开始广播」会现场编译旁路（系统自带 .NET Framework csc，几秒），之后走缓存；手机与电脑无需同一 WiFi（蓝牙直连），两边都要开蓝牙。
- 电脑单蓝牙芯片收不到自己的广播，属正常现象，空中可见性以手机端为准。
- **「已就绪但手机搜不到」排查顺序**：
  1. 日志里看**广播通道**：`GATT 可连接` 最理想（含服务 UUID）；若显示 `Publisher 退路`，说明本机蓝牙驱动不支持 GATT 广播——此时**广播仍在发**（Started），但广播里没有服务 UUID。
  2. 手机用 **nRF Connect 无过滤扫描** 15~30 秒：能搜到电脑名 = 广播正常，搜不到 = 手机端问题（距离、权限、蓝牙开关）。
  3. nRF Connect 能看到而目标 App 看不到 = **App 过滤条件**不匹配：按名字前缀过滤的 App → 改电脑名重启；强制按服务 UUID 过滤的 App → 本机驱动无解（Windows 拒绝在广播里放服务 UUID），退路是给电脑配一块十来块的 ESP32 板跑同协议固件。
- **换色延迟优化（2026-10-11）**：手机切色号后 PC 端点亮的等待主要耗在两处（vb_traffic 实录量化）——①回码 notify 是「写完成后才挂监听、先到先丢」的广播流，150ms 单发在 App 忙时错过就退化到 ~0.65s/条的读轮询（4 分片节目 3.5s+），现改为 **40~500ms 五连发**（挂载窗口落在哪儿都命中，全错过也有读轮询兜底不劣化）；②渲染原先要等 `0x01` 完成帧（它自己还要再等一轮回码），现改为**收齐分片即渲染**（分片连续性+总长校验在拼装时已做；缺片/不连续自动回落 0x01 正常路径）。主画布重绘（drawL2Panel 批量填充）非瓶颈。


**空状态提示**：设计模式下如果整块板还没有任何豆子，屏幕中央会出现友好引导卡（告诉你「导入图片」或「直接开画」）；如果画了内容但**从未保存过**，顶部会出现提醒条；如果筛选条件下**一格都没有**，会提示「当前筛选无结果」并给出一键清除筛选。这些提示都可以「不再提示」，且不遮挡画布操作。

### 3.7 项目存取与导出

- **保存**：工具条「保存」按钮或 `Ctrl+S` → 弹出**保存对话框**，可编辑项目名，确认后落盘为 `.pdp.json`（typed array 走 base64，104×104 全板仅约 29 KB）。文件含板参数、（可能已自定义的）调色板、beads、placedMask、校准档。

## 5. 物理校准五法

校准的目标只有一个：让「屏幕上两相邻钉位的距离」等于「你板上两相邻钉孔的真实距离」。
五种方法任选一种，结果都归一到同一份校准参数（`source` 字段会记录你用的哪一种）。

### 方法一 · 自动检测（桌面模式默认）

程序读取显示器物理厘米数与分辨率，直接算出 `mm/设备像素` 与分轴 PPI。
**零输入**，精度取决于系统/显示器 EDID 上报的物理尺寸是否真实（部分显示器会谎报）。
向导第 3 步会把实测值全部展示给你看，满意就直接用。

### 方法二 · 标尺拖拽法（最直观，**浏览器用户首选**）

1. 屏幕上画一条 **20 格标尺带**（带 mm 刻度），可切横向 / 纵向；
2. 把实物板贴在屏幕上，让板上的一排钉孔对准标尺带；
3. 拖滑块调钉距（范围 **2.400–3.000 mm**，步进 **0.001 mm**），直到屏幕格距与物理钉距完全重合；
4. 实时读数会同时告诉你：当前 pitch、整板在屏宽度、本屏 1:1 可容格数。

> 小技巧：不要只对 2 个钉孔，尽量让 20 格全部对齐 —— 累计长度越长，误差越小。

### 方法三 · 实测跨度法（最精确）

用尺子量「第 1 钉中心 → 第 K 钉中心」的毫米数，程序按 `pitchMm = mm / (K - 1)` 反推。
也可以直接量整板有效排豆区（如 104 钉板的 280mm）。
量得越长越准：量 50 钉的误差只有量 5 钉的十分之一。

### 方法四 · PPI / 对角线输入法

已知屏幕英寸数或对角像素时反推 PPI，再换算钉距。
适合手边没板子、但知道自己屏幕型号参数的情况。

### 方法五 · 拼豆模式内「整板对位」校准（推荐）

不用退出拼豆去开校准向导：拼豆模式的顶部常驻控制条点 `⚙` 展开高级面板，里面「尺子核对」小节有**整板对位**——

面板会显示当前屏上网格区的**理论尺寸**（分块时是当前块，如「整块豆阵应显示为 28.0×28.0cm」）。两种修法：

1. **逐轴实测反算（最准，专治两轴偏差不同）**：拿直尺量屏幕上网格区的实际宽、高（cm）填进输入框，点「按实测校正」。程序按轴解 `真 mm/px = 假设 mm/px × (实测 ÷ 理论)`——**长 27.8、宽 27.6 这种 X/Y 各偏各的也能一次修平**；只量一边就空着另一边。理论值（28.0cm）来自列数×钉距，是硬事实，拿它当基准最可靠。
2. **实物板贴屏同比例微调**：把实物板平贴屏幕，点「缩小 0.5% / −0.1% / +0.1% / 放大 0.5%」直到网格与板上钉孔逐格对齐。适合两轴偏差方向一致、手边没有直尺的情况。

校准结果仍按显示器存档（换屏自动带回）。如果实测校正的比率超出 ±50% 会被拒绝——先检查板参数里列数/钉距是否就是手中这块板（28cm 板 104 钉 = 2.6923mm）。

### 原点校准

除了钉距，还需要标定「第 (0,0) 钉在屏幕上的物理落点」：
屏幕上有一个**可拖拽的十字光标**（原点手柄），配合四角的 **L 形定位括标**，
把板角对准括标、十字拖到第一钉中心即可。

### 校准常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 整板比屏幕大一圈 | 板物理尺寸（28cm）大于屏幕可视区 | 正常。用**分块模式**（向导第 3 步会按屏幕容量建议最小分块，例如 1×2 两块） |
| 浏览器里拿不到物理尺寸 | 浏览器无权限读取显示器 EDID | 用方法二（标尺拖拽）或方法三 |
| 换了显示器后不准 | 校准档按显示器标识区分 | 程序会自动提示重新校准，重跑一次方法二即可 |
| 显示器选择器里某个屏置灰 | 虚拟屏（远程桌面 / 采集卡）无物理尺寸 | 不要选它，选真实物理屏；或在该屏上用标尺法手动校准 |
| 系统缩放（125%/150%）影响精度 | 设备像素 ≠ CSS 像素 | 程序内部全部在**设备像素域**计算，无需你处理；但请保持校准与使用时的缩放一致 |
| 拼豆模式整板与实物板对不上 | ①设计尺寸错（钉距/列数与实际板不符）②屏幕物理尺寸 EDID 谎报 | 先看「板参数」豆阵读数是否 = 实物板（否→实测反算钉距）；尺寸对但仍偏大偏小→用方法五「整板对位」或标尺法校准屏幕 mm |

### 6.3 双图对照 与 手机投图

**双图对照（图 A + 图 B，切「双板并排」布局）**——解决「同时看两张图 / 两张板各拼各的、还要分别控制」：

- **左画布 = 图 A（主图案）**：所有绘制、导入、撤销都在 A；**右画布 = 图 B（第二图案）**：只显不绘，独立板参数与区块分页。
- 每块画布顶部各有一条控制条：显示「图 A/图 B + 板尺寸 + 当前区块 + 左右翻页」；图 B 那条另有 **「拷贝 A→B」**（把主图快照过去做对照）与 **「清空」**（保留 B 板尺寸只清内容）。
- **两块可各自翻到不同区块**：例如图 A 拼第 1 块、图 B 显示第 2 块的样子做参考；也可以让图 B 走完全不同的图案（拷贝后各自编辑互不影响）。点某块画布即把它设为**激活**（边框高亮），投图/远程指令落到激活块。

**手机投图（左侧工具栏「手机投图」按钮）**——不用数据线、不用第三方软件，手机把图投到电脑：

1. 手机与电脑连**同一个 WiFi**；点「开启投图」，本机即起一个局域网小服务，对话框显示**二维码 + 上传页链接**。
2. 手机浏览器**扫码**（或复制链接）打开上传页 → 选图 → 选「投到 **图 A**（进导入向导，可裁剪配色）」或「**图 B**（按 B 板尺寸自动像素化，零操作直达对照屏）」→ 发送。
3. 电脑上即时落地：投 A 弹导入向导等你确认；投 B 自动走完「线性光采样 → 色度门控 → 量化 → CIEDE2000 匹配」直接进图 B。对话框收件箱列出每次投图的时间/目标/状态。
4. 完事点「停止服务」收回。**安全**：链接带随机 token（关服即失效）、只监听局域网、图片不上传任何外部服务器、转完即弃。仅桌面应用可用（浏览器模式无本机服务）。

> 拼豆模式的自动联动（全屏 / 锁 1:1 / 换布局 / 换主题 / 防休眠）**每一项都可以单独关掉**，
> 关掉后程序会记住你的偏好；退出拼豆模式时，程序会把你进入前的布局、主题、视图**逐项原样恢复**。

## 8. 浏览器模式降级说明

程序用同一套代码同时跑在 **Electron 桌面** 与 **普通浏览器** 里，靠一层「环境桥接」自动探测：
`window.pdb` 存在就走桌面分支，不存在就走浏览器降级分支。**你不需要手动切换**，
但要知道浏览器模式下哪些能力打折了：

| 能力 | 桌面模式（Electron） | 浏览器模式（降级） |
| --- | --- | --- |
| 显示器列表 | 系统 API，拿到全部显示器与工作区 | 只有 `window.screen`，**看不到多显示器** |
| 屏幕物理厘米数 | **WMI 实测**，自动高精度校准 | 拿不到（`physicalMm = null`）→ **必须手动标尺校准** |
| 全屏 | 原生无边框全屏，可**指定哪块显示器** | Fullscreen API（当前标签页全屏） |
| 防休眠 | 系统电源 API，稳定 | Wake Lock API，**不稳定**（切标签页 / 省电模式会失效），拿不到就静默降级 |
| 保存 / 打开 | 系统文件对话框 + 真实路径 | `showSaveFilePicker` → `<a download>` / `<input type=file>` |
| 自动保存镜像 | localStorage + `%APPDATA%\pindou-studio\` 双写 | 只有 localStorage（模拟 appData） |
| 最近项目 | 记住**文件路径**，一键重开 | 把**整份项目内容**存进本地存储 |
| 虚拟屏告警 | 能识别并置灰 | 无此概念 |

**浏览器模式的实际影响**：

1. 首次引导第 3 步会明确告知「浏览器模式无法自动获取物理尺寸，请用标尺拖拽法手动校准」；
2. 校准来源会标记为 `browser-fallback`，直到你手动校准过；
3. 清空浏览器数据 / 换浏览器 / 无痕模式，本地项目与最近列表会丢失 —— **请及时用「保存」导出 `.pdp.json` 到磁盘**；
4. Safari / Firefox 下保存会走直接下载，文件落在浏览器下载目录。

## 9. 色板来源与免责声明

> **请务必阅读本节。**屏幕上看到的颜色和手上真实豆子的颜色，本来就不可能完全一致。

### 9.1 内置色板的来源

| 色板 | 豆径 | 色数 | 来源 |
| --- | --- | --- | --- |
| **通用拼豆色板** | 2.6mm | 九大色族渐变阶梯 | **社区整理值** |
| **Artkal（阿缇卡）** | 2.6mm | 225 | S01–S159 核心系列：pixel-beads.com 色表核实 HEX；SE / ST / SL / SG / SN / SP / SUV / SD 共 66 色：官方未公布 HEX，按**颜色名称语义 + 色相/明度科学插值**推导的社区整理值 |
| **MARD** | 2.6mm | 221 | A1–M15 全部 221 色的 HEX 为 MARD 官方色卡（pd.anqstar.com/colors，2026-09 抓取）标注值；官方只给色号不给色名，中文名按「明度阶梯 + 色系」生成（如「浅黄橙」），可在颜色编辑器里改名 |
| **Perler** | 5mm | — | pixel-beads.com 色表 |
| **Hama** | 5mm | 90 | H01–H49 经典系：社区色表核实 HEX（缺号的 H14/H15 按透明系命名推导）；H55–H125 现代扩展 41 色：按项目需求补充的功能色（夜光/金属/半透明/粉彩/特殊色）按**名称语义 + 同族核实色的色相/明度科学插值**推导 |

### 9.2 免责声明（三条，都要知道）

1. **这些是社区整理值，不是厂商官方色卡数据。**
   部分色号（尤其是透明、亮片、夜光、珍珠、UV、条纹等**特殊材质豆**）官方从未公布 HEX，
   程序里的值是**按颜色名称语义与同族已核实色科学插值推导**出来的，仅供排版与配色参考。
2. **批次之间有色差。**
   同一色号在不同生产批次、不同年份、不同经销商之间本身就存在肉眼可见的偏差；
   再加上屏幕色域、色温、亮度、系统夜间模式的影响，**屏幕显示 ≠ 实物颜色**。
   因此：请把屏幕颜色当作「相对关系正确、绝对值仅供参考」的近似。
3. **可以用颜色编辑器 + 吸管实测校正。**
   如果你手上的豆子和屏幕差得明显，正确做法是：
   - 在自然光下给豆子拍一张照（或用扫描仪）；
   - 用程序的**吸管工具**（`I` 键）从照片上取真实颜色；
   - 在**颜色编辑器**里把对应色号的 HEX 改成实测值；
   - 需要长期复用的话，把校正后的色板**导出为 JSON 色板**（第 7 种导出产物），下次直接导入。
   - 自定义色板与内置数据**物理隔离**，内置色板永不会被你的修改污染；随时可以重置回默认。

### 9.3 实用建议

- **先买豆、后配色**：确定你手上是哪套豆子（品牌 + 豆径），再在程序里选对应色板，别用 5mm 的 Hama 色板配 2.6mm 的 Artkal 板。
- **减色时把颜色数压低**：24 色以内一般就够好看，色数越多，买到不齐的概率越大。
- **导出颜色清单当购物单**：CSV 颜色清单里有 `色号,名称,HEX,用量,已放置,剩余`，按「用量」备料。
- **特殊材质豆单独处理**：夜光 / 金属 / 半透明豆在屏幕上无法真实预览，建议在设计阶段就用普通色占位，实际拼的时候再替换。

## 13. 常见问题

**Q：程序打开是空白 / 一直转圈？**
A：多半是浏览器不支持 OffscreenCanvas 或 Worker 被拦截。程序会自动回退主线程执行，稍等即可；若仍不行，换 Chromium 内核浏览器或用 `npm run dev` 走桌面模式。

**Q：屏幕上的格距和我板子的钉距对不上？**
A：走第 5 节方法二（标尺拖拽法），把实物板贴在屏幕上拖滑块对齐。这是**唯一必须做对**的一步，其他都可以事后调。

**Q：104×104 的板在屏幕上放不下？**
A：这是**物理事实，不是 bug**。28cm 的板比大多数笔记本屏幕可视区都高。用**分块模式**：向导第 3 步会建议最小分块（通常 1×2，即上下两块整宽的 104×52），点「采用建议分块」；拼豆时按 `[` `]` 切区块，每块边缘有 L 形对齐括标与编号。

**Q：去背景之后看不出来哪些被去掉了？**
A：勾选「板参数 → 网格与标注 → 空格棋盘格」（默认开）：所有空格子会画成经典的灰白棋盘格（马赛克），被去背景清空的区域、图案的留空边缘一眼可辨，也与「有豆」的区域明确区分。不需要时取消勾选即可恢复主题底色。导入向导的实时预览同样用棋盘格表示空格。

**Q：生成的拼豆图看起来灰蒙蒙、颜色不准？**
A：按顺序检查：① 导入第③步把「饱和度」滑杆调到 +15～+25（匹配前生效，效果最直接），对比度 +5 左右；② 屏幕上发光的图和实物豆（反光的色素塑料）本来就有观感差，拼豆模式下用「进度 → 拼豆设置 → 发光底板增强」的亮度/饱和度滑杆按你的屏幕微调；③ 管线侧已经内置鲜艳度增强（vibrance）与近似色合并，实测高饱和色匹配后饱和度不降；④ 个别深色豆在纯黑底板上确实显暗——换「正常」筛选档对比看看。颜色最终以实物豆为准，可用吸管 + 颜色编辑器校正色板。

**Q：按 `Ctrl+S` 没反应？**
A：焦点可能在输入框里，或有弹框开着 —— 这时除 `Esc` 外全部快捷键失效（防止劫持打字）。先按 `Esc` 关掉弹框再试。

**Q：保存了但找不到文件？**
A：浏览器模式下文件可能直接落在浏览器下载目录；桌面模式会弹出系统保存对话框，注意看你选的路径。最近项目列表里也会记录。

**Q：想重看新手引导？**
A：工具条最右侧 **ⓘ「帮助」按钮** → 面板底部「重看新手引导」。

**Q：颜色怎么看都和实物不一样？**
A：正常，见第 9 节免责声明。用吸管 + 颜色编辑器实测校正，并把校正后的色板导出为 JSON 长期复用。

**Q：撤销会不会把整板清空？**
A：撤销栈用稀疏 diff，只回写受影响的格子；大范围操作会退化为快照。工具条的撤销按钮**会先告诉你这一步影响多少格**，看清楚再点。
